\begin{abstract}
% CS197 move 1a: problem motivation (failure mode) -- the general pattern: agents write the trust artifacts (tests, formal specifications) for their own code, so the artifacts themselves must be checked, at scale. "Trust artifacts" is the coined term; formal specifications are the concrete, objective instance (tests would also qualify).
When AI agents write their own trust artifacts, the tests and formal specifications that vouch for their code, those artifacts need checking at scale.
% CS197 move 1b: problem motivation (why a language-model judge) -- in end-to-end autoformalization with no scaffold, the agent picks its own interfaces and theorem decomposition, so the reference's tests and theorems cannot run against the candidate (representation mismatch gives false negatives) and a judge compares specifications semantically. Accuracy boundary: execution-based checking of generated specifications does exist when interfaces are compatible (nl2postcond), so the claim is the mismatch, not "tests can never validate checks". VeriBench is named and cited in the introduction only.
In end-to-end autoformalization, agents choose their own interfaces and theorems, so reference tests do not transfer and a language-model judge compares specifications instead.
% CS197 move 2: assumption (setup bit) -- the protocol we flip: collect human ratings, then trust the judge because its scores agree with them; re-check for every new model, prompt, and task. Repeat-stability is P4 in our suite, so it is not part of the flipped assumption. Terminology: "validation" for this human-agreement evidence, "screen" for our property checks, "certification" nowhere in prose.
The standard evidence that such a judge can be trusted is agreement with human ratings, a check repeated for every new model, prompt, and task.
% CS197 move 3: contribution (bit flip) -- collect labels once; screen every new judge with falsifiable properties whose required score response is fixed by construction, without consulting the labels again.
We propose instead to collect labels once and screen every new judge with falsifiable properties that fix how scores must respond to controlled edits.
% CS197 move 4a: instantiation (bit flip instantiation) -- Lean 4 specifications scored against a gold reference; the four properties P1-P4. "target", not "test": the headline panels have no missing-specification ladders, so P3 is proposed but unmeasured there (Section 5.2).
Four properties target identity, bug monotonicity, missing-specification monotonicity, and stability for Lean~4 specifications scored against a gold reference.
% CS197 move 4b: instantiation (bit flip instantiation) -- the fixed equal-weight index TI_var and the plain-words reason for its multiplicative form (Equation eq:tivar). The body never calls it a "trust index", so neither does the abstract.
A fixed equal-weight index, $\mathrm{TI}_{\mathrm{var}}$, combines bug monotonicity with two variance penalties multiplicatively, so no strong component can offset a weak one.
% CS197 move 5a: evaluation (setup and headline association) -- three families x eight configurations; "validation set" is the selection caveat (Sections 5.1 and 6), so no hedge clause here.
On a 72-pair validation set, the index tracks judge-level human agreement across three model families with eight configurations each.
% CS197 move 5b: evaluation (headline numbers) -- Codex panel Spearman 0.833 avg / 0.905 pass1 / 0.738 pass2; artifact experiments/archive/21_tmlr_submission/ci_provenance/headline_cis.json.
For the Codex panel, the Spearman correlation is 0.833 on averaged labels and 0.905 and 0.738 on the two rating passes.
% CS197 move 5c: evaluation (diagnostic result) -- the property report catches what human agreement misses: BAD_STRINGY rho 0.435 vs semantic prompts 0.365-0.466, 20/24 ladders with reversals (Table tab:codex_configs). The scalar's 0.940 stays in Section 5.3.
Bug-ladder checks expose a deliberately lexical judge that matches the semantic prompts' human agreement yet reverses on 20 of 24 ladders.
% CS197 move 6: implication (north star) -- Brando's approved closing (09-22-2026): "from X toward Y" vision, never a hedge; caveats live in move 5a and Section 6.
Judge validation thus moves from a per-judge annotation cost toward a one-time human panel plus automated, falsifiable checks that any new judge must pass.
