\section{Property Certification Protocol}\label{sec:property-protocol}
\paragraph{A one-time panel and reusable checks.}
Human ratings link judge behavior to the intended scoring task on a fixed validation set.
For each configuration, we measure agreement with those ratings and evaluate scripted perturbations of gold artifacts.
The perturbations require judge calls but no additional human labels.
We use the validation set to select the index form, prompts, repeat aggregation, and decision threshold.
After freezing these choices, subsequent configurations can face the same property checks without accessing the labels (Figure~\ref{fig:protocol}).
This is a screening protocol; the present evidence does not establish transfer to an unseen configuration or distribution.

\paragraph{Four falsifiable properties.}
\textbf{P1 (identity)} requires the maximum score when an artifact is compared with itself, $J_\theta(g,g)=1$.
\textbf{P2 (bug monotonicity)} requires non-increasing scores as errors accumulate.
The historical bug ladder used here alters the candidate text, including theorem statements; it is not restricted to implementation bugs.
\textbf{P3 (missing-specification monotonicity)} requires non-increasing scores as theorem statements and unit tests are removed.
We retain this historical property name although unit tests are not specifications under Section~\ref{sec:problem-setup}.
Each ladder extends the preceding level, so its expected ordering concerns cumulative damage rather than equal severity of individual edits.
Ties are allowed; a local score increase is a reversal.
\textbf{P4 (stability)} requires stable scores across repeated calls and meaning-preserving rewrites.
These include alpha-renaming, which consistently changes bound-variable names without changing their meaning.
The properties are targets for the probes; they are not theorems establishing the validity of every scripted transformation.

\paragraph{A fixed equal-weight summary.}
The protocol retains individual diagnostics because different failures need different checks.
Our primary scalar, $\mathrm{TI}_{\mathrm{var}}$, uses only bug-ladder scores, combining their average monotonicity with two variance penalties:
\begin{equation}
\mathrm{TI}_{\mathrm{var}}=\exp\!\left[\tfrac13\log C_f+\tfrac13\log(1-\widetilde V_c)+\tfrac13\log(1-\widetilde V_s)\right].
\label{eq:tivar}
\end{equation}
Here $C_f$ is the mean transformed per-file Spearman correlation between bug level and score.
$V_c$ is the variance of these per-file monotonicity values, and $V_s$ is the mean within-level variance across repeated calls.
The tildes denote min--max normalization across the configurations in the same family panel.
The implementation floors each logarithm's argument at $10^{-6}$.
Appendix~\ref{app:index-definitions} specifies aggregation, normalization, and undefined-correlation handling.

Multiplication prevents a strong component from fully offsetting a weak one; equal weights avoid fitting component weights to the human ratings.
The scalar nevertheless omits P1, P3, rewrite invariance, and a direct penalty for local reversals.
It therefore summarizes selected behavior rather than replacing the property report.
Moreover, panel-dependent normalization means that its absolute value can change when the comparison panel changes.
Using it prospectively requires a frozen normalization reference, whose transfer we have not tested.
