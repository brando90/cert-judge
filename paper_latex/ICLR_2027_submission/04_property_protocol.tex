\section{Screening Judges with Falsifiable Properties}\label{sec:property-protocol}
\paragraph{Labels once, checks for every judge.}
Figure~\ref{fig:protocol} and Table~\ref{tab:protocol_workflow} lay out the protocol.
A human panel rates candidate--gold pairs once; this validation set links judge behavior to the intended scoring task.
For each judge configuration, we measure agreement with those ratings and, separately, its responses to scripted edits of gold artifacts.
The edits require judge calls but no new labels.
We use the validation set to choose the index form, the prompts, the repeat aggregation, and the decision threshold, then freeze them.
A later configuration faces the same frozen checks without access to the labels.
The present evidence supports this as a screen; it does not establish transfer to an unseen configuration or artifact distribution (Section~\ref{sec:limitations-test}).

\paragraph{Four falsifiable properties.}
Each property fixes, by construction, how $J_\theta$ must respond to a scripted edit of a gold artifact $g$.
\textbf{P1 (identity)} requires the maximum score when an artifact is compared with itself or with a meaning-preserving rewrite of itself, $J_\theta(g,g)=1$.
The rewrites include alpha-renaming, which consistently changes bound-variable names without changing their meaning.
In the recorded panels, the identity summary uses four rewrite probes per artifact (renaming, reordering, style, and alpha-renaming); unedited self-comparisons appear at bug-ladder level 0 (Appendix~\ref{app:failure-diagnostics}).
\textbf{P2 (bug monotonicity)} requires non-increasing scores as bugs accumulate in the candidate.
The historical bug ladder used here edits the candidate text, including theorem statements; it is not restricted to implementation bugs.
\textbf{P3 (missing-specification monotonicity)} requires non-increasing scores as theorem statements and unit tests are removed.
We keep this historical name although unit tests are not specifications under Section~\ref{sec:problem-setup}.
Each ladder level extends the previous one, so the required ordering concerns cumulative damage, not equal severity of individual edits.
Ties are allowed; any local score increase is a reversal.
\textbf{P4 (stability)} requires stable scores across repeated calls on the same input.
The properties are targets for the probes, not theorems about every scripted transformation; Appendix~\ref{app:failure-diagnostics} records where the historical generators fall short.

\paragraph{A fixed equal-weight summary.}
Different failures need different checks, so the protocol keeps the per-property report.
For ranking configurations, we also use one scalar, $\mathrm{TI}_{\mathrm{var}}$, computed from bug-ladder scores only:
\begin{equation}
\mathrm{TI}_{\mathrm{var}}=\exp\!\left[\tfrac13\log C_f+\tfrac13\log(1-\widetilde V_c)+\tfrac13\log(1-\widetilde V_s)\right].
\label{eq:tivar}
\end{equation}
Here $C_f$ is the mean transformed per-file Spearman correlation between bug level and score, $V_c$ is the variance of these per-file values, and $V_s$ is the mean within-level variance across repeated calls.
The tildes denote min--max normalization across the configurations of the same family panel, and the implementation floors each logarithm's argument at $10^{-6}$ (Appendix~\ref{app:index-definitions}).
The geometric mean acts as a smooth conjunction: a strong component cannot fully offset a weak one, and equal weights avoid fitting component weights to the human ratings.
The scalar omits P1, P3, and a direct penalty for local reversals, so it summarizes selected behavior rather than replacing the report.
Its panel-dependent normalization also means that its absolute value can change when the comparison panel changes.
Prospective use therefore needs a frozen normalization reference, whose transfer we have not tested.
