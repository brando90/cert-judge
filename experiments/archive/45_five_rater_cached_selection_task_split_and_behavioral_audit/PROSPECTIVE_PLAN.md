# Integrated specification-weakening and gaming selection study

**Doc link:** <https://github.com/brando90/cert-judge/blob/main/experiments/archive/45_five_rater_cached_selection_task_split_and_behavioral_audit/PROSPECTIVE_PLAN.md>

**TLDR:** Compare behavioral selectors with the fixed human-rating rubric on the existing task split, using strict losses of meaningful guarantees and attacks certified to preserve those guarantees. New inference is not authorized; the executable manifest builder enumerates the proposed cells and their unmet admission conditions without calling a model.

## Decision and existing-evidence limit

The decision is whether behavioral screening selects judges with better five-rater agreement than uniform choice among the fixed H2 human-rating-rubric judges. The cached recovery preserves the 90% shared-support requirement. Its full-context validation pool has only 13/15 items because D0 cannot extract `2_heappush__agent0` and `binary_search__agent2`; the test pool also lacks `4_json_decoder__agent0`. Repeating model calls cannot fix a pre-inference extraction refusal. Do not silently drop D0 or relax the threshold. A prospective condition must either repair and separately identify its extraction contract, or declare a new pool before measuring; neither changes the frozen cached verdict.

Existing semantic probes establish elaboration and forward implication, but many changes remove guarantees still stated elsewhere. Existing file-level strictness judgments help separate this redundancy; failure to prove a reverse implication is not a counterexample. Existing gaming attacks use only six tasks from validation/test, and the reference judge credits many flagged edits. They provide no training-task attack data and no human ratings of edited files. An edited candidate is not licensed to inherit its original human score.

## One integrated pipeline

1. **Freeze source contracts before scores.** Keep all three historical candidates and all current ratings for each task in its established split. Record exact candidate, intent, reference, compiler, import and rubric hashes. Use existing current-five targets as primary, current-three as control, and old participant-one training-only auxiliary labels as a declared sensitivity. This remains reused evidence, including historical knowledge of test outcomes.
2. **Build a correct baseline for each task separately from benchmark references.** Require an audited mapping from intent to reference obligations, satisfiable preconditions, and no placeholder `True` guarantee. Work in an experiment-owned probe copy. Baseline/reference repairs are a separate future acceptance task; do not silently edit the benchmark. The five historical security placeholders and the baseline that failed prior elaboration stay blocked until this evidence exists.
3. **Remove meaningful guarantees cumulatively.** At levels 1–3, remove an obligation or weaken a predicate while holding implementation and remaining obligations fixed. Quantify over an arbitrary implementation. Prove that the conjunction of the earlier guarantees implies the later conjunction. Supply an explicit countermodel satisfying the entire later file but violating a named removed guarantee. Check satisfiability and compile each level using the pinned Lean toolchain, auditing axioms so `sorry` cannot certify the relation. A missing countermodel is `STRICTNESS_UNRESOLVED`, not a successful weakening. Check every adjacent step, not just baseline-to-final. The certificates compare the allowed behaviors of predicates after abstracting the implementation function; the scored files retain identical concrete implementation bytes. A countermodel may vary that abstract function, not the implementation bytes shown to the judge.
4. **Pair with harmless controls.** Use alpha-renaming and formatting with equivalent elaborated declarations; retain a proof of equivalence for renamed binders. Add vacuity and unsatisfiable-precondition probes with known relations. Keep formatting magnitude comparable to semantic edits where possible. A detector that penalizes every textual edit should fail the discrimination criterion.
5. **Include gaming in the same selection objective.** Fixed controls add redundant true unit tests, duplicate properties, irrelevant tautologies and score-seeking comments while preserving the file's meaningful guarantees. For adaptive attacks, give the attacker the candidate and scalar score only, with eight fixed rounds. Admit an edited file only if the implementation is unchanged and a separate relation checker certifies equivalence of its meaningful guarantee conjunction to the baseline; otherwise count the attempt as rejected. This tests score inflation without a real guarantee gain. It does not use a second language-model judge as ground truth. Keep code-injection or altered golds out of the comparison.
6. **Train, select, freeze, evaluate.** Develop checks and candidate screening rules only on ten training tasks. Use five validation tasks to choose among a finite declared set of at most three screening rules; freeze exact weights, aggregation, missingness and tie rules before test. Test once on the ten task groups. Report the paired human-agreement difference against fixed H2 and random selection, all-five versus three-rater sensitivity, absolute agreement/bias and repeat variability. Preserve every blocked or failed cell.

## Candidate screening rules and success

The cached three-rule set is deletion quality, strict weakening discrimination, and their geometric mean. For this future condition, add gaming resistance only after its valid training measurements exist: define resistance as one minus the clipped positive fresh-score gain on certified equivalent attacks, then combine with weakening discrimination by a geometric mean. Keep the final candidate-rule list at three and lock it before validation. This proposed change is not applied to cached outcomes.

Primary success: the chosen selector's expected test-task Spearman agreement exceeds fixed H2 by a positive lower 95% paired task-bootstrap bound. Also report Pearson and Kendall tau-b individually, mean absolute error, bias (judge minus human; positive means lenient), both means, and raw-repeat standard deviations. No superiority claim from a correlated proxy alone. Ten test tasks give limited precision; the interval is conditional on raters, source snapshots and the chosen models. An unresolved difference means the benefit remains unresolved, not that methods are equivalent.

## Proposed inference scope, not an admission

Use the existing twelve full-context test-judge configurations as a fixed comparison pool. The manifest lists every task/configuration pair, task split, and blocked admission state. Do not substitute models or drop cells after observing outcomes.

- Fixed probes: 25 tasks × 12 judges × 12 variants × 3 repeats = **10,800 judge calls**. Variants: identity, three strict weakening levels, alpha-renaming, formatting, vacuity, overconstraint, and four equivalent gaming controls.
- Adaptive attacks: 25 tasks × 12 judges × 8 rounds = **2,400 attacker calls**, at most **2,400 proposal-judge calls**, **300 initial scores**, and at most **1,800 fresh start/final judge scores** (three each). Total upper bound **6,900 calls**.
- Combined maximum **17,700 calls**, before any explicitly separate criterion-cache repair. Failed validity checks reduce admitted calls but remain in the declared denominator. They do not trigger replacement tasks or unbounded retries.
- Criterion repairs: **not yet quoted/admitted**; first resolve the extractor contract and freeze its changed configuration. Existing valid verdicts are never re-admitted.
- Funding route: proposed Valkyrie (Vals-funded), with no automatic dollar stop cap. Record actual platform charges, declared cells and single documented recovery. No provider keys or direct provider calls.
- Dollar estimate: **unavailable** until the exact eligible routes, prompts/token counts, attacker model and serving prices are verified. Past study totals are not a reliable quote for this new scope. No new inference is launched by this plan or its manifest builder.

## Executable follow-up and blockers

`python3 scripts/build_followup_manifest.py` enumerates the proposed 300 task/configuration cells and counts, reading only already-frozen metadata. It performs no inference and cannot load credentials. The output has `admission_authorized=false` and names the missing baseline, strictness, equivalent-attack checker, extractor and route/cost evidence. It is a scope artifact, not a runnable inference harness or an accepted scientific protocol.

Before any future run, register a separate active experiment, supply the baseline/proof artifacts and unit tests, freeze the inference and recovery contract, and verify its route authorization. Existing cached work is complete independently of this future condition; leaving this proposal does not make an experiment active.

## Cheapest discriminating first stage and stopping rules

The priorities below are judgments about information gained per effort, not measured cost estimates. No deadline forces a larger inference campaign now.

- **[p 9/10] Validate meaningful probe differences on the ten training tasks before any new judge scoring.** This addresses the immediate uncertainty: whether a judge can pass by counting declarations or reacting to superficial text. Build experiment-owned, compiler-checked implication and countermodel certificates for the complete conjunction of guarantees at every adjacent weakening step. Report each task as admitted or blocked, retaining all ten in the denominator. Stop inference admission if any declared task lacks an audited nonvacuous baseline or certificate; do not substitute a convenient task after scoring. No new calls are needed to discover that a proposed relation or baseline is invalid.
- **[p 8/10] Run the fixed weakening/control screen only after those checks and a scope/route quote.** Use three progressively weaker files, harmless controls, and equivalent gaming edits from the same task. This makes both semantic sensitivity and resistance to superficial score inflation observable in one comparison. The current strict-weakening screen ties eleven of twelve judges at its maximum on training tasks; more repeats of those same easy probes would not make the intended semantic distinction. The full 300-cell manifest is an upper-bound study design, not the cheapest first step or an authorization to run it.
- **[p 7/10] Admit adaptive gaming only after equivalent fixed attacks are valid.** Prefer a certified guarantee-preserving edit family as the attack space: manipulating scores within this family tests gaming without requiring invented human ratings of edited files. Adaptive attacks then test a stronger adversary than the fixed controls. A separate judge agreeing with the inflated score does not certify preserved or improved guarantees.

Certificates can establish compilation, implication, strictness, satisfiability, or invariance for encoded formal guarantees. They cannot establish that the baseline fully captures informal human intent, that a revised rubric matches the raters’ instruction regime, or that the selected judge transfers to new populations. Existing human ratings can still measure selection utility on the original rated outputs; they cannot be attached to edited attacks or newly repaired candidates. If all valid candidates for a screening rule tie, retain the tie and report no discrimination. If the fixed test interval spans zero, report unresolved superiority and retain all failed and missing cells. No new human collection is assumed by this plan.
