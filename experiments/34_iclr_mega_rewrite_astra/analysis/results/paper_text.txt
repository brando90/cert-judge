009                                               A BSTRACT
010
011            Large language models judge whether AI-written formal specifications express
012            the right guarantees, a question that running tests or checking proofs cannot settle.
013            Reliability is usually assessed through agreement with human ratings, leaving each
014            new judge configuration dependent on human validation. We propose collecting
015            labels once, then screening new judges with falsifiable properties that specify
016            how scores should respond to controlled edits. Four properties target identity,
017            bug monotonicity, missing-specification monotonicity, and stability for Lean 4
018            specifications. A fixed equal-weight index, TIvar , summarizes bug monotonicity
019
               and variance. We compare three judge families with eight configurations each
               on a 72-pair, single-annotator validation set that also informed protocol selection.
020
               For Codex, index–human-agreement Spearman correlations are 0.833 on averaged
021
               labels and 0.905 and 0.738 on the two rating passes. Bug-ladder reversals expose a
022            lexical grader that human agreement alone would favor, although the scalar index
023            still scores it highly. Judge validation thus moves toward a one-time human panel
024            plus automated, falsifiable checks that each new judge must face.

027   1    I NTRODUCTION
028
029
      AI agents write both programs and the checks intended to establish their correctness, including
030   tests (Haque et al., 2026) and formal specifications (Yang et al., 2024). Running a generated test
031   reveals whether the program and test agree, not whether either expresses the intended behavior. This
032   is an instance of the test-oracle problem: deciding which behavior should count as correct (Barr et al.,
033   2015). A formal specification states the guarantees a program should satisfy, such as returning a
034   sorted permutation of its input. Its role resembles that of a grading test, but a universally quantified
035   theorem covers every input rather than sampled cases (Claessen & Hughes, 2000). Lean can check a
036   proof of that theorem; it cannot establish that the author chose the right theorem (Lahiri, 2024).
037   Large language models (LLMs) already help replace the human oracle, filtering autoformalized
038   statements in theorem-proving pipelines (Lin et al., 2025; Wang et al., 2025). Human agreement is a
039   common criterion for validating these judges (Liu et al., 2023; Zheng et al., 2023). Agreement varies
040   across models, tasks, and evaluated properties, so evidence for one configuration does not establish
041   another’s reliability (Bavaresco et al., 2025). Existing labels can assess another judge on the same
042   examples without fresh annotation. However, repeatedly selecting judges against those labels risks
043   adaptive overfitting (Dwork et al., 2015). New artifact distributions also raise a separate question
044
      about whether those labels remain representative.
045   We propose using one human panel to assess a property suite, then screening subsequent judge
046   configurations without consulting those labels. The screen asks whether a judge responds appropri-
047   ately when a controlled edit preserves or damages a reference artifact. A failed property identifies a
048   concrete behavior that human agreement alone can hide. Passing the screen supplies evidence about
049   the tested behaviors, without guaranteeing agreement on unseen artifacts.
050   We instantiate this protocol for Lean 4 formal specifications judged against gold references (Figure 1).
051   Four properties test identity, responses to cumulative bugs, responses to removed theorem statements
052   and unit tests, and score stability. A fixed equal-weight index, TIvar , summarizes bug monotonicity
053   and two variance penalties. The full diagnostic suite remains necessary because this scalar omits
      some properties.

      On a 72-pair validation set, the index tracks judge-level human agreement across three families, each
055   containing eight configurations. The Codex association is Spearman 0.833, with a 95% bootstrap

057   form, prompts, aggregation, and threshold. A deliberately lexical judge agrees with humans yet

062          • A protocol that combines a one-time human validation set with four falsifiable properties for

064          • An evaluation linking committed scores to validation-set association, lexical failures, and

      2    R ELATED W ORK
068
069   LLM-as-a-judge validation. G-E VAL (Liu et al., 2023) and MT-B ENCH (Zheng et al., 2023)
070   compare judges with human ratings, leaving reliability dependent on the evaluated tasks and configu-
071   rations. Bavaresco et al. (Bavaresco et al., 2025) document this dependence across tasks rather than
072   establishing a universal judge. Schroeder and Wood-Doughty (Schroeder & Wood-Doughty, 2024)
073   measure consistency across repeated judgments, which does not by itself establish correctness. Our
074   protocol retains human agreement as a validation criterion and adds tests with specified directions of
075   response.
076
077   Judges for code. ICE-S CORE (Zhuo, 2024) and C ODE J UDGE (Tong & Zhang, 2024) use models to
078
      assess generated code where execution tests provide incomplete evidence, but their human-agreement
      results do not certify later judge configurations. SWT-B ENCH validates generated tests against
079
      developers’ fixes (Mündler et al., 2024), requiring a reference behavior rather than treating test
080
      execution as proof of test validity. Our controlled perturbations serve a related purpose for judges:
081   they specify how a score should change without labeling each perturbed artifact.
082
083   Judging formal statements. F ORMAL A LIGN learns alignment between informal and formal state-
084   ments (Lu et al., 2025), whereas our target is the behavior of a judge comparing candidate and gold
085   specifications. R E F ORM validates formal-statement judges against expert annotations (Chen et al.,
086   2026), without establishing that later configurations satisfy our behavioral properties. V ERI B ENCH
087   evaluates agent-generated Lean artifacts (Miranda et al., 2026); we study the judges used to score
088   their formal specifications. These tasks require checking what a statement means, beyond whether a
089   proof checker accepts it.

091   3    P ROBLEM S ETUP
092
093   Intent, specification, and artifact. An item contains an informal problem statement, a gold Lean 4
094   artifact g, and a candidate artifact x generated by an agent. We call the informal requirement the intent.
095   An artifact is a Lean source file containing an implementation and, potentially, theorem statements,
096   predicates, unit tests, and proofs. Its formal specification consists of the theorem statements about
097   the implementation together with the predicates they use. For example, a sorting specification can
098
      require both ordered output and preservation of the input elements. A proof certifies a theorem under
      its stated assumptions; it does not determine whether those requirements capture the intent. A unit
099
      test checks a concrete case and is not part of the specification under our terminology (Appendix F).
100
      We use “specification” in this sense regardless of who wrote it.
101
102   Reference-based specification quality. The target is how completely and correctly the candidate
103   specification captures the gold reference. A candidate can type-check yet omit a requirement, impose
104   an unintended assumption, or assert a vacuous property. The judge prompts ask which reference
105   guarantees the candidate captures and assign a score of zero to trivial statements such as True
106   (Appendix A). This scoring instruction does not establish that judges detect every such failure. A
107   gold reference supplies a concrete comparison target; it does not make the judge immune to strategic
      manipulation (Robertson & Koyejo, 2025).

143   4     P ROPERTY C ERTIFICATION P ROTOCOL
144
145   A one-time panel and reusable checks. Human ratings link judge behavior to the intended scoring
146   task on a fixed validation set. For each configuration, we measure agreement with those ratings and
147   evaluate scripted perturbations of gold artifacts. The perturbations require judge calls but no additional
148   human labels. We use the validation set to select the index form, prompts, repeat aggregation, and
149
      decision threshold. After freezing these choices, subsequent configurations can face the same property
      checks without accessing the labels (Figure 1). This is a screening protocol; the present evidence
150
      does not establish transfer to an unseen configuration or distribution.
151
152
153
      Four falsifiable properties. P1 (identity) requires the maximum score when an artifact is compared
      with itself, Jθ (g, g) = 1. P2 (bug monotonicity) requires non-increasing scores as errors accumulate.
154
      The historical bug ladder used here alters the candidate text, including theorem statements; it is not
155
      restricted to implementation bugs. P3 (missing-specification monotonicity) requires non-increasing
156   scores as theorem statements and unit tests are removed. We retain this historical property name
157   although unit tests are not specifications under Section 3. Each ladder extends the preceding level, so
158   its expected ordering concerns cumulative damage rather than equal severity of individual edits. Ties
159   are allowed; a local score increase is a reversal. P4 (stability) requires stable scores across repeated
160   calls and meaning-preserving rewrites. These include alpha-renaming, which consistently changes
161   bound-variable names without changing their meaning. The properties are targets for the probes; they
      are not theorems establishing the validity of every scripted transformation.

      A fixed equal-weight summary. The protocol retains individual diagnostics because different
163   failures need different checks. Our primary scalar, TIvar , uses only bug-ladder scores, combining
164   their average monotonicity with two variance penalties:
165                                    h                                              i
166                        TIvar = exp 13 log Cf + 13 log(1 − Vec ) + 31 log(1 − Ves ) .              (1)
167
168   Here Cf is the mean transformed per-file Spearman correlation between bug level and score. Vc is
169   the variance of these per-file monotonicity values, and Vs is the mean within-level variance across
170   repeated calls. The tildes denote min–max normalization across the configurations in the same
171   family panel. The implementation floors each logarithm’s argument at 10−6 . Appendix B specifies
172   aggregation, normalization, and undefined-correlation handling.
173   Multiplication prevents a strong component from fully offsetting a weak one; equal weights avoid
174   fitting component weights to the human ratings. The scalar nevertheless omits P1, P3, rewrite
175   invariance, and a direct penalty for local reversals. It therefore summarizes selected behavior rather
176   than replacing the property report. Moreover, panel-dependent normalization means that its absolute
177   value can change when the comparison panel changes. Using it prospectively requires a frozen
178   normalization reference, whose transfer we have not tested.

      5.1   DATA AND HUMAN PANEL
183
184   We evaluate candidate–gold pairs from V ERI B ENCH (Miranda et al., 2026). One annotator supplied
185   holistic ratings on a 0–5 scale in two passes, pass1 with a stricter rubric and pass2 with a more
186   lenient rubric. The collection covered 75 pairs from 25 problems with three agent generations per
187   problem. One gold filename could not be resolved, leaving 72 analyzed pairs from 24 problems. We
188   report each pass and the archived averaged-label view; they are two judgments by one person, not
189   independent annotators. Inter-pass agreement is Spearman 0.249, quadratic-weighted κ = 0.372,
190   and mean absolute error 0.771 on the shared pairs (Appendix D). These statistics describe label
191   disagreement; they do not establish an upper bound on judge agreement. The original written rubric
192
      was not recovered, so we cannot reconstruct every annotation instruction.
193   This panel is the validation set: it informed index-form selection, repeat aggregation, the threshold,
194   and the prompt panel, so correlations on it are optimistic. The fixed equal-weight TIvar has no
195   training set. A separate weight-tuned comparison uses these same pairs, and no analysis constitutes
196   a test-set result. For each judge, artifact-level agreement is the Spearman correlation between its
197   scores and the human ratings on the same analyzed pairs. We then ask whether the index orders
198
      configurations by that agreement.

354
355
356   Validation evidence and a different human criterion. The same labels informed the index form,
357
      repeat aggregation, threshold, and prompt panel, so the reported correlations are optimistic validation-
      set estimates. They involve one annotator and eight configurations per family, with shared controls
358
      rather than independent samples of eight models. No test-set result establishes reliability for a new
359
      judge or artifact distribution. We also collected 343 labels from five raters over 78 candidate–gold
360   pairs. That pool uses statement coverage with a theorem-spam deduction, a different rubric from the
361   panel’s holistic ratings. Its Spearman agreement with panel labels is approximately 0.13 on 63 shared
362   pairs.
363
      Two pre-registered screens asked whether property indices tracked agreement with that pool. The
364
      screen of 14 configurations was underpowered; the expanded screen of 32 found no index meeting
365
      its registered criterion. Its largest absolute Spearman association was −0.39 with Holm-adjusted
366   permutation p = 0.25; leave-one-out selection transfer yielded ρ = 0.24, p = 0.49. These negative
367   results do not demonstrate transfer under the original criterion, nor can the pool serve as a test set for
368   that criterion. Appendix D.3 records the corresponding negative-control evidence.
369
370
      Coverage of the screen. The probes do not establish sensitivity to vacuity, subtle weakening,
371
      over-constraint, or formatting-only edits beyond the four rewrites studied here. Constructing probes
372   with known directions for these failures is the next methodological step; we claim no result for
373   them. The historical alpha generator can produce malformed text, so its low scores do not establish
374   sensitivity to valid alpha-renaming. Other scripted rewrites and the intended ordering of bug edits
375   also lack semantic validation. We cannot separate rubric ambiguity from misunderstanding Lean
376   semantics with the current annotations. Presentation, including redundant theorems, implementation
377   bloat, and unnecessary abstraction, is unassessed; holistic human ratings may reflect it implicitly. We
      did not optimize candidates against the judge, so resistance to gaming is untested.

      All candidates and probes come from V ERI B ENCH in Lean 4. The protocol could be instantiated for
379   another proof assistant, but neither cross-assistant nor cross-benchmark transfer has been tested. A
380   score is relative to the supplied gold reference and extraction rule, not a guarantee that all intended

385   A locked test. A decisive test would first freeze the rubric, property generators, score extraction,
386   aggregation, index, normalization reference, and any rejection rule. Independent raters would
387   then label new candidate–gold pairs under that rubric, with new judge configurations fixed before
388   their labels are examined. The analysis would report both artifact-level agreement and judge-level
389
      association, including uncertainty and property-specific failures. A separate distribution-shift test
      would be needed for new domains. Because the original rubric text is unavailable, recovering it or
390
      validating an explicitly reconstructed criterion is a prerequisite to claiming a matched-rubric test.

393   7   C ONCLUSION
394
395   A one-time human panel can support a protocol that screens new judges through falsifiable behavioral
396   checks without collecting labels for each configuration. On the present validation set, the fixed
397   equal-weight index is associated with human agreement, but its high scores can coexist with lexical
398
      failures. Individual property diagnostics therefore remain essential, and a locked test must establish
      transfer beyond the labels used to select the protocol. The goal is to make human judgment a reusable
399
      foundation for checking new judges, with each judge accountable to explicit tests of its behavior.

      F    U NIT T ESTS AS G ROUND T HEOREMS : A D EFINITION W E D O N OT A DOPT
887
888
      Section 3 follows common formal-methods usage: the formal specification consists of theorem
889   statements about the implementation, and unit tests are not part of it. We record a competing view that
890   we do not adopt. In Lean 4, a unit test is often itself a closed theorem. The gold myAdd artifact states
891   its tests as, e.g., example : myAdd 1 2 = 3 := by native_decide, an anonymous
892   theorem with no free variables. On this view, a unit test specifies the implementation at one concrete
893   input, and specifications range from such ground instances to universally quantified properties such
894   as ∀n, myAdd n 0 = n. The choice changes terminology, not our measurements. The P3 ladder
895   removes theorem statements and unit tests alike; under the adopted definition, only the removed
896   theorems count as missing specification.
